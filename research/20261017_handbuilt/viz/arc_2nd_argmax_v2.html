Inside a tiny neural network that finds the second-largest number

A small neural network reads ten numbers, one at a time. Its job is to say where the second-largest number is.

It has just 16 neurons. Nobody designed how it works: it learned by training. It is right about 95 times in 100. Below, the real network runs in your browser.

How it works, in short

  1. It remembers the largest number so far.
  2. Each positive number starts a clock that records when it arrived. The output can't see the clocks.
  3. When a bigger number arrives, the old largest's clock turns into a vote for its position.
  4. Numbers close to the second-largest also get a vote. Smaller numbers are forgotten.
  5. Each step, the votes move along, so at the end they point at the right positions.
  6. The highest vote wins. Near-ties are sometimes decided wrongly.

The sections below show each step on the real network.

1. Keeping the largest number

Neuron 4 fires only when a number beats the largest so far, in proportion to how much it beats it by. Neuron 2 adds up those jumps one step later, so it holds the largest number (about 17 times it), one step behind. It starts to forget after about four steps.

2. The hidden clock

Put a single positive number in, with zeros elsewhere. Ten neurons start to turn like the hand of a clock, about 40° per step. Below, those ten neurons are drawn as a point in the plane where they turn.

The network's output cannot see this clock. Its two copies push the ten scores in opposite directions and cancel. So the scores stay almost equal, and the lone number gets no vote. That is right: the largest number must never be the answer.

3. A new largest number reveals the old one

Now use two numbers: a bigger one (1.5) and a smaller one (1.0). The answer is the smaller one's position.

If the smaller comes after the bigger, it gets its own vote when it arrives (see the next section). The interesting case is the other order. The bigger number arrives second and pushes four neurons (1, 6, 7 and 8) to zero. Those four held one copy of the smaller number's clock. With that copy wiped, the other copy shows, as a vote for the smaller number's position.

4. Who gets a vote: neuron 5

Most numbers are neither the largest nor the second-largest, and they must not vote. Otherwise the many small votes would drown the right one. Neuron 5 decides. One step after a number arrives, it compares that number with the second-largest so far. It fires only if the number is close: above about 0.8 of it. Then the number keeps a vote. Otherwise it is forgotten.

Here the largest is 2.0 at position 1 and the second-largest so far is 1.0 at position 3. Move the number at position 6.

Number at position 6:

Notice that the switch sits below the second-largest, not at it. So a number a little smaller than the second still keeps a full vote, and two votes compete. The network seems to hedge: it knows the second-largest only roughly, and missing a real new second costs more than an extra competing vote. Moving the switch up to exactly the second gains only about half a point of accuracy, and moving it slightly too high costs more.

5. Votes move with time

A vote must end up at the right position, but it is placed when its number arrives, before the network knows how many steps remain. The network solves this by moving every vote one position each step. The grid shows, after each step, the scores the network would give if the input ended there. Blue is high, red is low, and the ring marks the highest score in each row.

Before the end, a vote sits to the right of its number's position, one place for each step still to come. Each step it moves one place left, so it lands on the number's position exactly at the end. Follow a ringed cell down the grid to see it move. The last row is the real answer.

6. Close calls

About 1 input in 20 is answered wrongly. Most mistakes happen when the second- and third-largest are nearly equal. Then both have votes, and the bigger vote should win. But votes are not perfectly sized: depending on positions, one is a few percent too big or too small.

Which side wins a near-tie differs from one trained network to another. In 22 networks trained the same way, these patterns were essentially unrelated. Changing this network's weights by half a percent reshuffles them. So the mistakes come from fine detail in the weights, not from a rule. The only pattern shared across networks is small: when the largest came first, the later of two nearly tied numbers is favoured by about 1%.

7. The weights

The whole network is 432 numbers, shown below. Each row is one neuron, grouped by role. The first column is how strongly the input reaches that neuron. The middle block is how strongly each neuron feeds this one at the next step. The last block is how this neuron adds to each of the ten scores. Blue is positive, red negative. Hover over a cell to see its value.

A few weights carry the steps above:

  • Input column. Neuron 4 gets +10, so a large number makes it fire. Neurons 1, 6, 7 and 8 get −11 to −13, so a large number pushes them below zero and wipes them. All the others get almost nothing.
  • Neurons 2 and 4. Neuron 2 keeps 0.97 of itself and adds 1.7 × neuron 4: it adds up the jumps. Neuron 4 subtracts 0.49 × neuron 2, so it fires only above the stored largest. It also subtracts its own last value (−0.99), a trick that makes the stored largest exact despite the one-step delay. ARC's hand-designed version of this task uses the same trick.
  • Neuron 5. It takes −0.6 and −0.85 from neurons 7 and 8. So it fires when a number has pushed them down a lot. Its biggest output weight (+3.4) goes to the score of position 8, the vote for a number one step old.

    What we don't know yet

    • Why neuron 5's switch sits near 0.8 of the second-largest, and why it varies between inputs (from about 0.6 to 0.85).
    • Why the clock needs neuron 3's help at certain positions.
    • How votes interact in detail. A simple model where each number casts an independent vote matches the network's answers 95% of the time. But it matches only about a quarter of the network's mistakes.
