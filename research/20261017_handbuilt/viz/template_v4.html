Inside a tiny neural network that finds the second-largest number

A small neural network reads a list of ten numbers, one at a time. When it has read all ten, it names the position of the second-largest number.

The network has 16 neurons. Nobody programmed how it does the task: it learned by training on random lists. It is right about 95 times in 100. The real network runs in your browser on this page, so everything you see is computed live.

The answer in one paragraph

At the end the network gives each position a score, and the highest score is its answer. To make the right position win, it does three things as it reads:

  1. It remembers the largest number so far.
  2. For each positive number it keeps a record of when that number arrived. The record of the current largest is kept hidden, so it cannot raise any score. When a bigger number arrives, the old largest's record is unhidden and raises the score of the old largest's position. The old largest has just become the second-largest, so that is the right position.
  3. A number that arrives later than the largest and is at least about three-quarters of the second-largest so far also raises its own position's score. Smaller numbers leave almost no lasting trace.

Example: the list starts 1.0, then 1.5. When 1.5 arrives, the record of the 1.0 is unhidden and raises the score of position 0. If a 1.2 came later, it would raise its own position's score more, and win.

The rest of the page shows each part of this on the real network, building up from one number to a full list. Everything shown is measured by running the network on chosen lists. Nothing here is derived from the weights alone, and that difference matters for ARC's challenge (see the end).

1. What a neuron is here

Each neuron holds one number, called its activity. Activity is never negative. A neuron with activity above zero is said to fire.

The network reads the list one number per step. At each step every neuron computes its new activity from two things: the number just read, and the activities of all 16 neurons at the previous step. It multiplies each of these by a fixed weight, adds them up, and sets the result to zero if it is negative. The weights were set by training and never change.

After the last step, the network computes ten scores, one per position, again as weighted sums of the 16 activities. The position with the highest score is the answer. Only differences between scores matter, so the charts show each score minus the average of the ten. Below, step through the list and watch the activities and scores change. Scores only mean something after the last step. Before that, the figure shows what the network would answer if the list ended there. We call a pattern of activity that raises one position's score above the others a vote for that position.

2. Remembering the largest number

Two neurons keep the largest number seen so far. Neuron 4 fires only when a new number beats the largest so far, by an amount that grows with the margin. Neuron 2 adds up neuron 4's output, one step later. So neuron 2's activity is roughly 17 times the largest number so far. The 17 is just the scale training happened to choose. Neuron 4 is not a perfect detector: on random lists, about 1 time in 15 it also fires weakly for a number just below the largest.

3. One number alone: a hidden timer

Give the network a list of zeros with a single 1 in it. Click a box to move the 1.

After the 1 arrives, twelve of the neurons change together in a regular way. Seen as a group, they act like the hand of a clock: the hand turns about 40° at each step (blue dots, one per step). The output reads this hand like a dial. Each position has a spoke (grey lines), and the spokes for positions 0 to 7 sit about 40° apart. A spoke's score rises when the hand points along it. At the end of the list, the hand points at the spoke of the 1's own position. So the hand is a timer: it records how long ago the number arrived, which is the same as where it is.

Yet the scores on the right stay almost flat. The other four neurons (1, 6, 7 and 8) carry a mirror copy of the timer that pushes the scores the opposite way, and the two cancel. So a lone number gets no vote. That is what the task needs: the first number is always the largest so far, and the largest must never win. Nobody designed this; training found weights that hide the timer this way.

Two positions are read differently. Position 8 (a vote one step old) and position 9 (the last number) are read mostly through other neurons, not through the dial, so their spokes are short.

4. Two numbers: a bigger number unhides the timer

Now use two numbers: a smaller one (1.0) and, later, a bigger one (1.5), with zeros elsewhere. The right answer is the smaller one's position. When the bigger number arrives, it pushes neurons 1, 6, 7 and 8 to exactly zero: the input reaches them with a strong negative weight. Their copy of the smaller number's timer is erased, and the twelve neurons' copy no longer cancels. It becomes a vote for the smaller number's position. (From the next step, the four neurons fill up again, with the bigger number's timer, which stays hidden.)

We can test this claim directly. Take a second list that is the same except that its smaller number sits somewhere else. At the moment the bigger number arrives, copy the twelve neurons' activities from that second list into the first. If the twelve hold "where the smaller number arrived", the answer should jump to the second list's position.

Over all 240 such pairs of lists, copying the twelve neurons moves the answer to the second list's position every time. Copying neurons 1, 6, 7 and 8 instead never does, and copying twelve neurons picked at random does so only 34–59% of the time. With random small numbers in place of the zeros, the result is the same.

When the smaller number arrives after the bigger one, there is nothing to unhide. It gets its own vote when it arrives, through neuron 5. That is the next section.

5. Three numbers: who gets a vote

Most numbers in a list are neither the largest nor the second-largest. They must not get votes, or many small votes would drown the right one. One neuron decides: neuron 5. One step after a number arrives, neuron 5 fires only if that number is at least about three-quarters of the second-largest so far (or bigger). If it fires, the number keeps a vote. If not, the number leaves no lasting trace.

Here the list has a largest number (2.0 at position 1), a second-largest so far at position 3, and a third number at position 6. You set both of their sizes. The other numbers are −0.3.

The switch sits below the second-largest, at about three-quarters of it in this example. Its place varies with the other numbers in the list: on random lists we measured it anywhere from about 0.6 to 0.85 of the second-largest. So a number slightly smaller than the second-largest still keeps a vote, and the two votes compete. The bigger vote usually wins.

Why not switch exactly at the second-largest? Our guess, not proven: the network knows the second-largest only roughly, and missing a real new second-largest costs more than letting a slightly smaller number vote. In a test not shown on this page, where we moved the switch by hand, moving it up to exactly the second-largest gained only about half a point of accuracy, and moving it slightly higher lost more.

6. Votes move one place per step

A vote is created when its number arrives, but the network does not know how many numbers are still to come. It handles this by moving every vote one position to the left at each step. A vote created at the newest position therefore ends up exactly at its number's position when the list ends.

7. Close calls: where the network goes wrong

The network is wrong on about 1 list in 20. Most of these mistakes happen when the second- and third-largest numbers are nearly equal. Both then have votes, and the bigger vote should win. But votes are not sized perfectly: depending on where the numbers sit, a vote can be a few percent too large or too small. When the two numbers are within a few percent of each other, that is enough to pick the wrong one.

Two further results from our analysis, not shown on this page: we compared 22 networks trained the same way. They make their close-call mistakes at different places: which of two nearly equal numbers wins depends on tiny details of each network's weights. Changing this network's weights by half a percent already moves many of these decisions. So which side wins a close call follows no simple rule. Whether the overall rate of mistakes can be predicted from the weights is a separate, open question.

8. The weights

The whole network is 432 numbers: 16 weights from the input, 16 × 16 between neurons, and 16 × 10 to the scores. Each row below is one neuron. The first column is the weight from the input number. The middle block holds the weights from each neuron's activity at the previous step. The right block holds the weights to the ten scores. Blue is positive, red negative. Rows and columns are sorted into the groups used above. Outlined cells are the weights named below. Hover for exact values, and click a neuron number to highlight everything into and out of it.

  • Input column: neuron 4 gets +10, which is why it fires for a large new number. Neurons 1, 6, 7 and 8 get −11 to −13, which is why a large number pushes them to zero (section 4). The other inputs are near zero.
  • Neuron 2 keeps 0.97 of its own activity and adds 1.7 times neuron 4's: it adds up the jumps (section 2). Neuron 4 gets −0.49 from neuron 2, so it only fires above the stored largest.
  • Neuron 5 gets −0.6 and −0.85 from neurons 7 and 8. A number that pushed those two far down makes neuron 5 fire one step later (section 5).

9. Checking the explanation by building the network by hand

If an explanation is right and complete, it should be enough to build a working network. We tried: a second 16-neuron network of the same form, with every weight written down from the explanation, and none trained. It gets 98.9% of random lists right.

The first attempt failed, and the failure was informative. We had built it from an earlier version of the explanation, in which every smaller number left a lasting vote. A simulation of that rule reached only about 88%, even with votes as sharp as the trained network's, because the many small votes crowd each other out. Measuring the trained network then showed what was missing: it forgets numbers well below the second-largest after one step (section 5).

The hand-built network is not a copy of the trained one. It keeps exactly one lasting vote and erases it when a new second-largest arrives, where the trained network keeps several and lets them compete. And its switches are far sharper: its largest weights are about 1,000, against about 13 in the trained network. So its higher accuracy says the parts are enough to solve the task, not that it matches how the trained network works. Both pass the same simple two-number checks, which shows how little those checks test. You can run it in the playground below.

    What we don't know yet

    • Why neuron 5's switch sits where it does, and why it shifts from list to list.
    • Neuron 3 is small but carries information about where the second-largest is: it is more active when the second-largest sits at position 0, 1 or 6, and scrambling it hurts positions 1, 5 and 6 most. We don't know why the timer needs this help there.
    • How votes interact in detail. A simple model where each number casts an independent vote agrees with the network's answers 95% of the time, but reproduces only about a quarter of its mistakes.

    Where this stands

    This network is called M16,10 in ARC's post AlgZoo: uninterpreted models with fewer than 1,500 parameters (Jacob Hilton, January 2026). ARC's challenge is stricter than explaining how it works: estimate its accuracy from the weights alone, without running it on random lists, and do so at least as accurately as random sampling with the same compute. This page does not meet that challenge. It describes the algorithm from measurements; the close-call errors that set the accuracy are exactly the part it cannot yet derive from the weights.

    Earlier work: ARC's post described the neurons that track the largest number. In comments on the post, Nicholas Goldowsky-Dill fitted neurons 1, 6, 7 and 8 as combinations of the largest and second-largest so far, and Martin Keane described the position memory as a rotating "phase wheel", which is the timer here.

    The network file is one_layer_16_hidden_94_acc_2nd_argmax. (Its file name says 94% accuracy; we measured 95.3% on 100 million random lists.) The lists are random numbers from a bell curve centred on zero. For readers who know the notation: each step computes h ← ReLU(Whh h + Whi x), where ReLU sets negative values to zero and there are no constant (bias) terms; the scores are Woh h.
