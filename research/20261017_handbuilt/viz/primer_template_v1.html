Second-largest, step by step

How a 16-neuron network finds the second-largest of ten numbers, built up from nothing, one small animation at a time.

This page explains our work on one tiny trained network, from the ground up. It starts with the task, builds a cartoon of the algorithm, then turns each piece of the cartoon into neurons. Only then does it show the trained network doing the same thing, with its real numbers. The last part covers what we built by hand, what is still unsolved, and where the network's mistakes come from.

Each figure is a short animation. Press ▶ to move one step, ◀ to go back, or play to run it. The text under each figure changes with every step and says what just happened.

1The game

You are shown ten numbers, one at a time. Each is drawn at random from a bell curve centred on zero, so about half are negative and most lie between −2 and 2. After the tenth, you must name the position (0 to 9) of the second-largest number. Not its value: where it was.

ARC's AlgZoo collection includes a recurrent network trained to do this. It is called M16,10: 16 neurons, lists of 10. It is right on 95.3% of random lists. ARC posed it as a puzzle: explain how it works, well enough to estimate its accuracy without running it.

2What the network is allowed to do

The network's whole memory is 16 numbers, one per neuron. We call a neuron's number its activity. All 16 start at zero.

At each step the network reads one number from the list. Each neuron then computes a weighted sum: the new number times one weight, plus each of the 16 old activities times its own weight. If the sum is negative, the neuron sets its activity to zero instead. This rule, "keep it if positive, else zero", is called ReLU. It is the only bend in the whole machine. Everything else is adding and multiplying by fixed weights.

After the tenth number, the network makes ten scores, one per position. Each score is another weighted sum of the 16 activities. The position with the highest score is the answer. The weights were set by training and never change. There are 432 of them.

activity after ReLUnegative sum, set to zero by ReLU

Two facts about this machine shape everything that follows.

It has no clock. Nothing tells the network which step it is on. To remember where a number was, it has to start something when the number arrives that changes in a regular way at every later step. That something is the subject of sections 5 and 6.

Only ratios matter. There is no constant term in any sum (no "bias"). So if every number in the list is doubled, every sum doubles, every activity doubles, and every score doubles. The answer cannot change. Press "× 2 every number" above to see it. This is why every threshold in this story is a fraction of another number, like "at least three-quarters of the second-largest so far", never a fixed value like "above 0.5".

3A cartoon of the answer

Before any neurons, here is the algorithm in pictures. It is the plan the trained network follows, cleaned up.

When a positive number arrives, it may drop a token onto a conveyor belt. The token's height is the number's value. Each token drops in at the right end and slides one place left at every step. So when the list ends, every token sits exactly under the number that made it. At the end, the tallest visible token names the answer.

If every positive number dropped a visible token, the tallest token would always be the largest number. The fix has three rules:

  1. Hide the current largest. A new largest drops a hidden token (dashed outline).
  2. Unhide on overtaking. When a bigger number arrives, the old largest's token becomes visible. The old largest has just become the second-largest, so its token is the right one to show.
  3. Forget small numbers. A number that is not a new largest drops a visible token only if it beats the second-largest so far. Anything smaller can never end up second, so it is dropped.

With rules 1 and 2, the cartoon is right on … of random lists (computed in your browser on 100,000 lists). It fails only on lists with at most one positive number, about 1 in 100. Negative numbers drop no tokens, so the cartoon cannot rank them. The trained network also loses most of these lists.

Rule 3 changes nothing in the cartoon, because its tokens are perfectly sharp: a token at position 3 adds nothing to position 4. In a network, tokens are blurred, and many small blurred tokens can add up and outvote the right one. That is why the trained network forgets, as section 9 shows.

4Neurons I: the largest so far

The first job is to know the largest number so far. ReLU does comparisons for free: ReLU(10 × (x − largest)) is zero unless x beats the largest, and then it is ten times the margin.

The trained network does exactly this with two neurons. Neuron 4 fires only when a new number beats the largest so far, at about ten times the margin. Neuron 2 adds up neuron 4's output one step later, so it holds about 17 times the largest so far. Neuron 4 also subtracts its own previous activity (weight −0.99), which stops the stored value from being counted twice. ARC's own hand-designed network uses the same trick.

true largest so farneuron 2 ÷ 17neuron 4 ÷ 10 (fires on a new largest)

Neuron 2 lags one step, and it overshoots by up to about 10%. The rest of the network corrects for the lag by reading neuron 4 as well.

5Neurons II: a timer is a turning arrow

The conveyor belt needs the network to remember when a number arrived. With no clock, the simplest way is something that turns. Picture an arrow that appears when the number arrives and turns 40° at every step. Its angle then says how many steps ago the number came, and since the list always has ten numbers, that says where it was.

Two neurons are enough to hold such an arrow: one for its left–right part and one for its up–down part. Turning by 40° is a fixed weighted mix of the two, which is exactly what one step of the network computes.

The output reads the arrow with one spoke per position. A position's score is the arrow's shadow on that position's spoke: big when the arrow points along the spoke, smaller when it points 40° away (cos 40° ≈ 0.77), negative when it points away.

In the trained network the arrow is real. Twelve of its sixteen neurons move together, and 96% of their movement lies in one flat plane. Seen in that plane, after the first two steps, they turn about 40° per step, clockwise. The output's weights for positions 0 to 7 also point in position order, about 43° apart, so at the end of the list the arrow points at the spoke of its number's own position. This holds for numbers two to eight steps old. The newest positions and position 0 are read in other ways. Choose "Trained network" above to see it, with a single 1.0 in an otherwise empty list.

Notice the shadow chart. With one arrow, a number at position 4 also lifts positions 3 and 5 to about three-quarters of its height. A vote read through one arrow is a broad wave, not a sharp spike. That blur is the problem the next section solves.

6Several arrows make a conveyor belt

One arrow gives a broad wave. Add a second arrow that turns twice as fast (80° per step), a third at 120° and a fourth at 160°. Each arrow's shadow is a wave around the same position, but faster arrows give narrower waves. Added together, the four waves cancel everywhere except at the token's own position.

This is the conveyor belt of section 3, written in a different way. Nine slots on a belt and four turning arrows plus one constant are two descriptions of the same nine numbers. Mathematicians call the switch between them a Fourier transform. You can watch it below: tick the arrows one by one and see the wave sharpen into a spike.

arrows:

The trained network's twelve neurons contain such a set. Fixing which neurons are on and off (the most common pattern in the middle of the list), each step multiplies the twelve by one matrix. That matrix has turning pairs at about 43°, 83°, 125° and 180° per step, close to the 40°, 80°, 120° and 160° of a nine-slot belt. Each pair shrinks to 0.84–0.95 of its size per step, so the belt fades.

A second check comes from the output weights alone. If the twelve neurons are a belt, then the weights that read position k+1 should equal the weights that read position k, pushed one step forward through the matrix. They do, with a similarity (cosine) of 0.97. Neighbouring rows of output weights on their own are only 0.56 alike. Of 21 other trained networks, 17 show the same relation. So the timer is a fading belt of about nine slots, seen through turning coordinates, and the output reads it with weights that turn along with it.

One consequence matters later. Because the reading turns with the belt, a vote reads the same height at its own position whatever its age, and every vote has the same shape around its position. So the network's decisions look like fair votes, even though its activities fade.

7Neurons III: hiding the largest's vote

Now rule 1 of the cartoon: the current largest must not vote. The trained network does something surprising. The largest's timer runs anyway, in the twelve timer neurons. Four other neurons, 1, 6, 7 and 8, build an exact mirror of it. At the output, the timer pushes the scores one way and the mirror pushes them back by the same amount. We call these four the hiding neurons.

Below, the list holds one 1.0 and nine zeros. The bars show the final scores, split by where the push comes from. Each part is shown relative to its own average over the ten positions, because only differences between scores matter.

push from the twelve timer neuronspush from the four hiding neuronstotal score

The two pushes are each about 50 at their peak, and they cancel to within a few units. The final step above is the key experiment of the whole project in miniature: switch the four hiding neurons off by hand, with no bigger number anywhere, and the largest's hidden vote appears at its own position.

8A bigger number unhides it

Rule 2 of the cartoon: when a bigger number arrives, the old largest must start to vote. In the trained network this costs nothing extra. The hiding neurons have large negative input weights, −11 to −13. Each holds a value tied to the largest so far, so an ordinary number cannot push it below zero. A number bigger than the largest does push it below zero, and ReLU sets it to exactly zero. The mirror vanishes, and the old largest's timer becomes a visible vote.

The chart now shows the scores the output would read at each step, using the same output weights. Because the reading turns with the belt (section 6), a vote shows up displaced to the right by the number of steps still to come, and it slides one place left per step. It lands on its own position at the end, like a cartoon token.

The four hiding neurons rebuild from the new largest within a few steps, so the 1.5's own timer is hidden in turn. The output cannot read the newest one or two positions through the belt. Position 8 is read mostly through neuron 5 (next section) and position 9 through the dip the last number causes in the hiding neurons. That is why the right end of these charts is messy before the list is complete.

9Keep or forget: neuron 5

Rule 3: forget small numbers. One step after a number arrives, neuron 5 fires if the number is at least about three-quarters of the second-largest so far. Every new largest passes too. A number that passes is kept and starts a visible vote. A number that fails is forgotten: one step later its effect on the scores falls from about 55 per unit of size to about 1.

Below, a 1.5 at position 1 and a 1.0 at position 3 come first, so the second-largest so far is 1.0. Move the third number and watch neuron 5.

Why forget at all, if a small number's token can never win? Because votes in the network are blurred (section 5), and blurred votes add. Our first account said every number votes. An idealized model built on that account reached only 24–43% with a single turning arrow, and about 88% even with votes as sharp as the network's, because many small votes crowded out the right one. That failure sent us back to measure the network on full random lists instead of two-number lists, and that is where neuron 5's forgetting showed up. On two-number lists every positive number is the largest or the second, so there is nothing to forget, and the gate is invisible.

Forcing neuron 5 off one step after the true second-largest arrives drops accuracy on such lists from 96% to 0%. Forcing it off when a new largest arrives makes the answer wrong in 36 of 36 test lists.

11Proof by construction: a hand-built network

An explanation might sound right and still be missing a piece. A strong test is to build the network by hand from the explanation alone, with every weight set from a written rule and nothing trained or tuned against accuracy. If the parts are right, the hand-built network should work.

Our hand-built network has the trained network's form and size: 16 neurons, ReLU, no bias. It is right on 98.97% of random lists, more than the trained network's 95.3%. Earlier hand-built networks for this task needed 21 or 22 neurons.

Below, both networks read the same list. The hand-built network's reading is almost a cartoon: the score at each surviving vote's position is that number's own value.

The hand-built network differs from the trained one in three ways. It uses weights up to about 500, so its switches are sharp; the trained network's largest weight is about 13. It keeps every positive number instead of forgetting small ones. Instead, one step after an overtaking, its whole belt dips by a share of the old largest. That dip trims the old largest's wave to a single spike and wipes out older, smaller votes. And its belt does not fade.

Building it also corrected the account. Our first version of the explanation said every number votes. A model built that way could not reach the trained network's accuracy (section 9), which is how we found neuron 5.

12The unsolved part: copying the roles

The hand-built network matches the trained one in size, but it uses its own version of each part. The harder test is a network that gives each group of neurons the trained network's exact job, neuron group by neuron group. We call it the role-copying network. It has the store and detector (trained neurons 2 and 4), a keep-or-forget gate relative to the second-largest (neuron 5), a gate that fires one step after a new largest (neuron 9), three hiding neurons plus one that stores the second-largest (1, 6, 7, 8), and eight belt neurons.

Hover over a bar for its value.

The role-copying network is right on 97–99% of lists, except one kind: when a new largest arrives at the very last step, it drops to 11%. Here is why, in plain terms. Its hiding neurons rebuild their mirror from the stored largest at each step. That rebuild leaves a constant extra amount in them, which the output removes using the stored largest. When the new largest arrives on the last step, the hiding neurons have just been wiped, so the extra amount is gone. The output still subtracts it, which creates a false vote.

Our sharp-switching designs needed one or two more neurons to fix this: 17 neurons reach 96%, 18 reach 98%. That is not a proof that 16 is impossible. The trained network does manage with 16, at 94% on these lists. We measured three ways it seems to manage, each with a different kind of evidence:

  1. Smooth comparisons instead of sharp switches (evidence: counts and a swap test). Its hiding neurons switch off gradually, starting near 0.9 of the largest. At the last step the detector and the hiding neurons decide together. The price shows up in its mistakes: with a rival at 0.97 of the old largest, it errs 17% of the time when the new largest is only 1% bigger than the old one, and 4% when it is 30% bigger.
  2. A clock driven by the jump (evidence: fits). After a new largest, the hiding neurons push about "new value minus 0.7 × old value", not "new value". A new largest at the last step therefore leaves no stale correction.
  3. A belt that splits its work (evidence: interventions on twin lists). Two steps after an overtaking, belt neurons 10–13 change with the jump, while neurons 0, 14 and 15 are pushed down by the old largest's value. Copying either group from a twin list lowers how often the network names the old largest from 98% to 60–87%. So the trained network does dip its belt by the old value, like our hand-built network, but only in a few neurons. Our role-copying network dipped the whole belt, which also clipped the new largest's wave.

Our current 16-neuron attempt has the first two and reaches 70%. Its remaining problem is that an overtaken largest's wave spills about 0.7 of its peak onto the neighbouring positions. Trimming that spill without also trimming the new largest's wave, which enters the same belt neurons on the same step, is the open design question. Mechanism 3 suggests the answer: put the two waves in different belt neurons.

13Where the mistakes come from

The trained network's mistakes are almost all close calls. About 61% name the third-largest instead of the second, mostly when the two differ by under 3%. About 15% name the largest, almost all within 3%. About 18% are lists with at most one positive number. The remaining 6% name the fourth or lower.

To see a close call up close, fix the largest at 1.6 and the second at 1.0, set every other number to −0.46, and slide the third-largest's value from 0.90 to 1.10. A perfect network would switch from the second's position to the third's exactly at 1.00. Pick the positions below.

The offset of the switch point from 1.00 is that placement's bias, typically about 2%. The network errs on any list where the second and third are closer than the bias, on the wrong side. Biases are stable within one network, but they look random across networks. Across 22 networks trained the same way, their patterns are essentially unrelated (median correlation 0.02). Changing one network's weights by half a percent reshuffles them. We found no simple rule that predicts them: per-position vote sizes explain about a third of their spread.

14An accuracy estimate, and ARC's challenge

ARC's challenge asks for a mechanistic estimate: predict the network's accuracy from an understanding of its weights, at least as well as random sampling does for the same amount of computing.

If biases behave like random noise, only their size should matter. So our estimate adds three terms: lists with at most one positive number, close calls between the second and third, and close calls between the largest and second. Each close-call term multiplies how often random lists produce a near-tie of a given width (pure probability) by how wide the network's wrong band is, averaged over the 720 placements of the top three. The wrong bands are computed exactly: with no bias terms, the network is exactly linear between the points where a neuron switches on or off, so we walk each line one linear piece at a time.

Each dot is one trained network. Filled dots were used while developing the estimate; open dots were scored only afterwards. The line is a perfect estimate.

The estimate misses by about 0.65 percentage points on the 22 development networks and 1.0 on the 16 later ones. That is far better than guessing the average (2.3 and 3.5). But it costs about 53,000 network runs per network, and random sampling with 53,000 lists misses by only about 0.1 points. So it does not meet ARC's challenge. At its cost, it is worth about 400–1,000 random lists. Its main gaps: mistakes that name the fourth-largest or lower (about half a point), a largest-versus-second term that runs low, and the assumption that the 720 fixed lines represent all lists.

Two lessons for interpretability came out of the work. First, rebuilding by hand found what checks on simple inputs missed: the forgetting gate is invisible on two-number lists. Second, a summary model that agrees with 95% of the network's answers but repeats few of its mistakes is not necessarily missing a mechanism. The same summary repeats even fewer of the hand-built network's mistakes, whose mechanism we know completely. Mistakes depend on fine details that a summary does not encode.
