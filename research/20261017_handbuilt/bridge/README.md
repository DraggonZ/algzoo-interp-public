# Bridging the hand-built network to the trained one (2026-10-18)

**Summary.** After exact relabelling and rescaling (same function), the 16-neuron hand-built network built at the trained network's gain scale (92%; 95% with only the clock gain raised to 50) has nearly the trained input weights (cosine 0.99, which largely follows from matching each neuron's loudness) and the same largest-so-far pair (cosine 1.00); the drive into its hiding neurons is similar but not the same (cosine 0.82). Six of the eight trained memory neurons are 86-97% linear functions of its memory's contents, but a random rotating memory or a leaky-integrator bank fed the same writes does nearly as well (81-96%): the two networks write the same things into memory, and the test does not tell how the trained network stores them (neurons 3 and 15 are small differences of large terms). Its 4-point loss at the trained scale is not partial switching: records that win by too little to wipe the hiding group fully are as common in the trained network, but v18's margin on those lists is a hundred times smaller (review below). The trained hiding neurons compare the current number with references between the second-largest and the largest; right after a record two of them compare it with the second-largest. Figure: `fig_bridge.png`. Several readings were later corrected; corrections are marked where they apply.

Aim (2026-10-18): keep working on understanding and on bringing the hand-built network closer to the trained one, with 16 neurons, not 28. Weights still come from rules only; the relabelling and rescaling below are exact symmetries (no fitting).

## What was done

- `../paper/tweet/match_order_scale.py`: relabel v18's neurons to the trained neuron with the same job (inside the clock and memory groups, the trained neuron whose activity it tracks best: one-to-one assignment by correlation), and scale each neuron (incoming × c, outgoing / c, c > 0) to fire as loudly as its partner (RMS on random lists). Same function (logits within 1e-9). Clock neurons track trained 7, 6, 1 at r = 0.99, 0.93, 0.93; memory slots track trained memory neurons at 0.49-0.89. Figure `../paper/tweet/matched_heatmaps.png`. Input weights then nearly coincide (detector 10.3 against 10.2; hiding neurons −9.5, −9.9, −12.8 against −10.6, −11.0, −13.2); the largest-so-far 2×2 block matches (`../paper/tweet/make_match.py`, `weights_match.png`).
- Trained memory block eigenvalues (8×8 block of neurons 0, 3, 10-15, all on): 0° (1.02), ±38° (0.82), ±84° (1.00), ±127° (0.86), 180° (0.92). Agrees with NOTE item 7 (full network's common on/off pattern: ±43, ±83, ±125, 180).
- `vote_profile.py`: a kept number's vote in the trained network is broad (peak 23-42 per unit at its own position, neighbours +5 to +15, distant positions down to −20, position 9 about −33); v18's is a sharp 0.25 at its own position.
- `ideal_kernel.py`, `ideal_angles.py`: idealized vote model (keep rule 0.75 × second-largest, largest hidden). Sharp votes 99.0%. A band-limited kernel on a regular 45° grid aliases positions 0 and 8 (77%). The trained memory's irregular angles give a kernel that is nearly sharp out to offset 6 (|K| ≤ 0.1) and pushes the aliasing to offsets 7-9 (−0.43, 0.65, 0.58): 86.5%. A 40° grid without 160° gives 87.1%. Reading (interpretation): eight memory neurons cannot hold sharp votes for nine or ten positions; the trained network's uneven rotation rates keep nearby votes sharp and leave the error on the farthest pairs, which other paths (position 9's own readout, fading) can absorb.
- `cyclic_memory.py`, `cyclic_memory2.py`: making v18's memory wrap around (slot 7 into slot 0). With the forward copies kept, 38% (the record's wave is written twice). Without them the detector's injection already writes the whole 8-periodic wave: identical on lists with no overtaking (99.0% both), but 58-71% on lists with overtakings, 68% overall, because an overtaken record's wave then stays at positions after the overtaking, where v18 never writes it.
- `record_profile.py`, `tail_cancel.py`: what the trained memory and cancelling neurons hold for a record (nudge the record; final-score change by group, median). While the record stays largest, the memory holds a broad wave and the cancellers its negative (total within about 8 per unit everywhere). After an overtaking the profiles mix the old record's wave with the new record's jump (the new jump falls when the old record rises), so these medians do not separate old-tail cancellation from new-jump hiding. Not yet resolved.
- `modal_memory.py`: v18's memory rewritten exactly in rotating coordinates (real Fourier basis over the 8 slots plus a level of 0.97 × the store's largest; logits within 5e-9). Its block still has eigenvalues near 0 (it shifts votes out; the trained block recirculates), and after matching loudness the weights from v18's clock and flip into it are in the thousands, because v18's neurons ride on large levels. Figure `modal_matched_heatmaps.png`. It does not make the heatmap look much closer.

## Where the remaining difference is

Observation: after exact relabelling and rescaling, v18 matches the trained network in the input weights, the largest-so-far pair and the clock-to-canceller rotation. It differs in two places: (1) its hiding neurons ride on large levels cancelled again in the readout (readout weights in the hundreds after rescaling, trained about 6), the source of its fragility; (2) its memory is a delay line that writes each record's hiding wave slot by slot and stops writing it when the record is overtaken, while the trained memory recirculates, holding the wave as rotating patterns. Making v18's memory recirculate costs 28 points, all on lists with overtakings. Open question: how the trained network keeps an overtaken record's recirculating wave from spoiling later positions.

## How the trained memory writes and stops a record's hiding wave

- `tail_cancel2.py`, `.log`: nudging the overtaken record and the overtaking number together (new jump fixed). In the trained network the revealed vote is a bump at the record's position (29-49 per unit), with the scores after the overtaking summing to between −27 and +19 per unit, and strongly negative at much earlier positions (down to −88 at position 0 for a record at 4). In v18 it is 0.25 at the record's position and zero elsewhere (v18 votes at 0.25 per unit).
- `tail_switch.py`, `.log`: leaving neuron 0, neuron 15 or all memory neurons unclipped does not bring the tail back (sums after the overtaking change by a few points), though it raises the revealed vote (34 to 46-48) and costs accuracy (95.3% to 76%, 88%, 44%). So memory switching is not what cuts the tail.
- `feed_test.py`, `feed_split.py`, logs: the memory's share of a hidden record's profile changes when either the detector's weights into the memory or the hiding neurons' weights into the memory are zeroed; both feeds write it, as in v18 (detector once, clock and flip step by step). The detector's share lies mostly at and before the record's position (trained 0.53, 0.90, 0.83 of its size for records at 2, 4, 6, against 0.33, 0.56, 0.78 for a spread-out profile; v18 1.00). The hiding neurons' share is spread out in both networks, so this test does not show whether the trained hiding neurons write mainly the part after the record, as v18's forward copies do. Interpretation: the trained memory may stop writing an overtaken record's wave the way v18 does, because the feed from the hiding neurons stops when they are silenced; untested directly.

## Negative result: keeping the hiding neurons' feed does not bring the tail back

- `feed_keep.py`, `.log`: after the overtaking, the memory received the hiding neurons' feed from a copy of the list in which they were not silenced. The tail after the overtaking changed little (sums −27 to −35, −3 to −17, −2 to −4, +19 to +18 per unit for the four placements). So the stopped feed is not what keeps the overtaken record's wave off later positions. Mechanism still unknown.

## Neurons 3 and 15: small differences of large terms

- `n3_n15_residual.py`: what v18's neurons leave of trained 3 and 15 (45% and 43% of variance at step 5) is not explained by any single named quantity (squared correlation at most 0.05).
- `n3_n15_pre.py`: the pre-activation (before the ReLU) of neuron 15 is matched at 0.86 against 0.79 after it; it is off on a fifth of steps, so part of its gap is switching. Neuron 3's pre-activation is matched at 0.66 only.
- `n3_cancel.py`: both are small differences of large terms. A neuron's pre-activation divided by the summed sizes of its terms, median: neuron 3 0.04, neuron 15 0.05; other memory neurons 0.13-0.43. Rebuilding neuron 3's pre-activation from the trained weights applied to v18's matches of its inputs gives 0.67-0.74, the same as matching it directly. Reading: neurons 3 and 15 need not hold anything v18 lacks; they subtract large, well-matched terms (neuron 3: −1.23 × neuron 0, +1.20 × neuron 1, −1.07 × neuron 8, ...), which amplifies the small mismatches by about 20-25 times. What their small differences are for is still open (neuron 3 helps positions 1, 5 and 6).

## Partial switching does not appear in v18 at the trained gain scale

- `partial_switch_scale.py`, `.log`: share of positive non-record numbers k steps after a new largest at which some but not all hiding neurons are off. Trained: 0.63, 0.54, 0.43 for k = 1, 2, 3. v18 at gains 10,000: 0 everywhere; at gains 10: 0.02-0.04. v18's clock level g (m1 − x) covers its wave except when a number comes within a few hundredths of the largest; the trained hiding neurons' wave is about a quarter of their level (`robust_twin/wave_level.log`), so ordinary numbers cut it. Lowering the gains alone does not make v18 switch like the trained network.

## The one gain that matters, and the trade it exposes

- `gain_one_at_a_time.py`, `g_sweep.py`, logs: from the trained-scale build (92.1%), only the clock level gain g matters: g = 100 gives 95.5% with every other gain at 10; the detector, flag and tie-breaker gains change accuracy by under half a point. Over g = 10, 15, 20, 30, 50, 100, 300 accuracy rises 92.1, 93.3, 93.9, 94.6, 95.1, 95.5, 95.6% while the share of numbers one step after a record at which the hiding group is partly off falls 3.8, 2.5, 1.9, 1.2, 0.7, 0.3, 0.1%: about one point of accuracy per point of partial switching.
- `g50_v18.py`, `v18g50_matched_heatmaps.png`: at g = 50 (95.1%) the matched input weights and largest-so-far pair look the same as at g = 10, but the hiding neurons' readout weights grow to about ±35, five times the trained network's ±6, because the readout must pick a small wave off a larger level.
- Reading: in v18's design, small readout weights (trained-like) and accuracy exclude each other, because a clock level small enough to keep the readout small lets ordinary numbers partly switch the clock off, and v18 is not built for that. The trained network has both, partly switching on about 60% of such steps (`partial_switch_scale.log`), and undoing its partial switching costs 24 points (NOTE). This is the clearest form so far of the open question of how it uses partial switching.

## Why partial switching does not break the trained network's hiding

- `g10_errors.py`, `.log`: v18 at g = 10 partly switches on 16% of lists and is right on 68% of them (96.5% elsewhere); 42% of its errors name the largest, so its hiding leaks (at g = 10,000: 2%). The trained network partly switches on 78% of lists and is right on 95.7% of them (94.4% elsewhere); 20% of its errors name the largest.
- `clip_consistency2.py`, `.log` (`clip_consistency.py` is a first version that also undid full silencing, which is not partial switching): in the trained network, at steps where the hiding group is partly off, feed the memory the hiding neurons' unclipped pre-activations instead of their clipped values: accuracy 95.4% to 87.9%, errors naming the largest 20% to 47%. Reading the hiding neurons unclipped at the last step only: 94.3%, errors naming the largest 35%. So the memory must take in the clipped values for the hiding to hold.
- Retracted reading (2026-10-18, same session): "the memory builds its copy from the clipped values, so a clip changes the wave and its copy together". Two later results undercut it. First, a control with the same change at the same steps but random signs costs as much or more, in ARC's network and in 15 other trained networks (`clip_consistency_across2.log`: feeding unclipped values costs 1-84 points, random signs 1-76). Second, undoing the partial clipping consistently, in the hiding neurons themselves so everything downstream sees unclipped values, already costs 24 points (NOTE, `gao/partial_function.log`). So partial clipping does work of its own in the trained network, and the rest of the network is sensitive to changes of that size at those steps; the interventions do not single out consistency of the hidden wave and its copy. What partial clipping computes is still open.

## Across networks

- `clip_consistency_across.py`, `clip_consistency_across2.py`, logs: in the 16 trained networks with at least two hiding neurons (85% rule), lists with a partial switch: 32-87%. Feeding every other neuron the hiding neurons' unclipped values at partial switches costs 1 to 84 points (ARC 18, new111 84); the same change with random signs costs about as much (ARC 21, new111 76). Networks that switch partly more often lose more. This shows sensitivity to changes of that size, not a specific need for the clipped values.

## The largest stays hidden through partial switching in the trained network, not in v18

- `hidden_after_clip.py`, `.log`: lists with a largest at r = 2-5 that stays largest; leak per unit = change of its own score minus the median change elsewhere when it is nudged. Trained: −5 to −9 per unit with a later partial switch, −4 to −6 without (votes are 30-40 per unit). v18 at g = 10: about −63 per unit after a partial switch (6 times its vote of 10), 0 without. v18 at g = 10,000 does not partly switch.
- `hidden_consistency.py`, `.log`: in the trained network the leak per unit stays at −4 to −7 under consistent unclipping (accuracy 71%), memory fed unclipped (88%) and memory fed random signs (84%). So none of these interventions costs accuracy by unhiding the largest's own value; they act through the numbers that cause the partial switches.
- Reading (interpretation): a partial switch never corrupts the trained network's hiding of the largest's value, while in v18 it corrupts it for the rest of the list. A likely reason, from earlier measurements: the trained hiding neurons are a rotation that shrinks about 6% per step and is re-driven every step by the store and detector (19% of their wave; `robust_twin/trained_drive.log`), and they regain their size after a disruption at once (angle of the full state 13°, then 8°, then 6°; `robust_twin/trained_recover.log`), though their turning pattern only slowly (72°, 66°, 44° with the shared level removed; `recover_redrive_wave.log`). v18's clock is an undamped rotation with no re-drive, so a clip's error stays. Design consequence to test: a damped clock re-driven by a source that holds the record's phase.
- `store_redrive.py`, `.log`: giving the hiding neurons 15.9 × the largest instead of the store's value (which also carries when the largest arrived) drops accuracy from 95.4% to 69.7% and shifts the leak per unit from −4 to −6 to −8 to −13, about equally with and without a later partial switch; the same replacement for the memory's input (control) drops accuracy to 64.2%. So the store's timing signal matters everywhere, and this test does not show that it is what protects the hiding at partial switches. Open.

## What partial switching right after a record is: a comparison with the second-largest

- `clip_recovery.py`, `.log`: lists with a largest at step 2 and a positive number at step 3 that partly switches the hiding group (65% of such lists in the trained network, 3% in v18 at g = 10). Against the same list with that number set to 0, the hiding group's sensitivity to the largest turns by only 0.8-1.7° over steps 3-9, size unchanged. In v18 at g = 10 it turns by 19-26° and stays turned.
- `clip_which.py`, `clip_which2.py`, logs: in the trained network the neurons that clip are those that carry the least of the largest at that step: at the step after the record, 6 (all such lists) and 8 (96%), whose sensitivity to the largest is 0 even without the clip; the clipped neurons hold 2-16% of the group's sensitivity at steps 3-6. In v18 the clipped clock neuron holds 22-72%.
- `n6_n8_threshold.py`, `.log`: one step after a record the four were silenced the step before, so their pre-activation is linear (variance matched 1.00 over all such lists; the review found about two-thirds near the switch-off point, where records that win by little leave the four partly on and the state before is not zero) in the previous largest p (now the second-largest), the new largest m1 and the arriving number x:

| Neuron | Pre-activation one step after a record | Off when |
|---|---|---|
| 6 | 11.05 p − 0.50 m1 − 11.00 x | x above about 0.9-1.0 p (off 30% at 0.85-0.95 p, 90% at 0.95-1.05 p) |
| 8 | 13.05 p − 0.39 m1 − 12.31 x | x above about p (off 38% at 0.95-1.05 p) |
| 7 | −0.10 p + 13.41 m1 − 13.17 x | x above m1 (a new record) |
| 1 | 1.76 p + 8.80 m1 − 10.56 x | x above about m1 |

Reading: right after a record, neurons 7 and 1 hold the new largest minus the arriving number and pick up the record's jump from the detector, while neurons 6 and 8 still hold the previous largest (through the store, which lags one step) minus the arriving number. So 6 and 8 compare the number right after a record with the second-largest, and that is the partial switch: it happens to neurons that do not yet carry the new record's wave, so it costs the hiding nothing. This accounts for three earlier findings at once: the cancelling neurons carry the previous record and the number after the current largest (resampling, NOTE), the vote of the number right after a record sits in neuron 8 and is erased by an overtaking (`gao/r2_route.log`), and the hiding survives partial switching. Later partial switches (steps r + 2 on) also fall mostly on the neurons with the least of the record's wave (`clip_which2.log`), as the wave rotates into 6 and 8.
- Design consequence (proposal, not built): a hand-built hiding group could inject a record's jump into two of its neurons only and let the rotation carry it to the other two, so that for a step or two those two hold the previous largest minus the arriving number: a second-largest comparison for free, whose clipping costs the hiding nothing.
- `second_comparator_across.py`, `.log`: the same fit in the 18 trained networks that have hiding neurons (85% rule; 4 have none). Every fit matches 0.98-1.00 of variance. In 8 networks (ARC, zoo3, new101, new104, new106, new111, new113, new115) at least one hiding neuron holds about k (p − x) with a weight on the new largest under 0.3 of its weight on p; new106 has ARC's exact pattern (two neurons on p, two on the new largest). In 4 more (new102, new107, new108, new109) a hiding neuron weights p more than the new largest, but not cleanly. In 2 (zoo2, new103) the hiding neurons carry about ±740-880 on p and the new largest, that is about −800 × the jump: any record silences them for a while, a different design. In 4 (zoo0, zoo4, new100, new105) all hiding neurons compare with the new largest. So a second-largest comparison right after a record is common but not universal. (The criterion was chosen after seeing ARC's pattern.)

## Proposal for the next hand-built network (not built; needs approval)

From the trained network's hiding group as measured above, a 16-neuron design that keeps v18's other parts and replaces its clock (3 neurons) and flip (1) by four hiding neurons built like trained 1, 6, 7 and 8:

- Each holds a level of about 11-13 × (largest − current number) plus its share of a 2-D phase that turns about 43° per step (the trained block: one rotating pair shrinking 6% per step, the other two directions dying out within a step, so the level is supplied afresh every step from the store and the input).
- The record's jump is injected only into the two neurons whose share of the phase is positive at that angle (trained 1 and 7: 0.9 and 1.3 from the detector; 6 and 8: about 0), so nothing is pushed below zero by the injection.
- The two neurons that get no jump read their level from the store alone, which lags one step, so for the step after a record they hold the previous largest minus the arriving number: the second-largest comparison, whose switching costs the hiding nothing.
- The memory's copy of the wave and the readout's dials would be re-derived for four directions instead of three plus the flip; the flip's 180° sharpening is lost, so the revealed vote is broader and the network would need the trained network's erasure (the number after a record stored in the clipped neurons and deleted by an overtaking) to keep accuracy.

What would test it: accuracy at trained gains (target about 95%), robustness to 1% noise, whether its partial switching matches the trained network's (63% one step after a record), and the matched-heatmap similarity of the hiding block. Open risk: the readout's phase extraction with two neurons sometimes clipped is no longer exact; the trained network tolerates this at 95% and how is not fully known.

## Where v18 loses at small gains: incomplete wipes by small new records

- `g10_where.py`, `.log`: v18 at g = 10. Lists with no partial switch and no incomplete wipe (84% of lists): 96.5%, the same as at large gains. A record that beats the previous largest by too little to push the clock's level g (m1 − x) below its phase leaves the clock partly on: 6.3% of records after a positive number, on 7.7% of lists, which are right only 45% of the time. One partial switch after a record: 72-95% depending on the step. So most of the small-gain loss (92.1% against 96.0%) is incomplete wipes, and partial switches add the rest. The correlation in `g_sweep.log` between accuracy and partial switching partly stood in for this: both shrink as g grows.

## Recovery after an early silencing is slow for the pattern (correction)

- `recover_redrive.py`, logs: a kept number within 5% below the largest silences the hiding neurons fully or partly. Full-state angle to the undisturbed state, 0-3 steps later: 49°, 13°, 8°, 6° (as `robust_twin/trained_recover.log`); with the store's timing signal removed from their input, 90°, 19°, 12°, 9°. With each state's mean over the four removed (the turning pattern only): 44°, 72°, 66°, 44°; without the store's timing, 90°, 90°, 90°, 67°. So the earlier reading that they recover within a step or two described their shared level; their pattern recovers slowly, and the store's timing signal helps it recover.

## The hiding neurons as comparators with references between the second-largest and the largest

- `hiding_steps.py`, `hiding_reference.py`, logs: with negative numbers between, each trained hiding neuron's pre-activation k = 1-5 steps after a record is linear (variance matched 1.00 over these lists) and close to c (ref − x), with c about 11-13 and ref = (a p + b m1) / (a + b), a weighted average of the previous largest p and the new largest m1 (a + b within 0.87-1.02 of c). Share of the new largest in the reference, k = 1..5: neuron 7: 1.01, 1.01, 1.00, 0.87, 0.73; neuron 1: 0.84, −0.03, 0.33, 0.90, 1.26; neuron 6: −0.05, 0.75, 1.06, 1.15, 1.06; neuron 8: −0.03, 0.30, 0.06, 0.09, 0.50. So neuron 7 compares the current number with the largest, and the other three with references that rotate between the second-largest and the largest, staying mostly within them. The previous largest is carried by the group's own recurrence: the arriving number's term from the step before cancels across the group (for neuron 8: +14.4 − 7.6 − 6.7 from neurons 7, 8 and 1), which is the block's fast-dying direction.
- Reading (interpretation): with references in [p, m1], any new largest switches all four off however small its lead (`robust_twin/trained_wipe.log`: pre-activations negative even at jumps under 0.01), and a number below the second-largest never switches any off; they switch only for numbers between the second-largest and the largest. `partial_split.log`, `partial_split_fine.log`: with a previous largest above 0.2, numbers below half of it never partly switch the group, 0.80-0.85 of it 14%, 0.90-0.95 42%, 0.95-1.00 80%, above it 99-100%; with no positive number before the record, 6 and 8 are always off.
- `ref_shift_oracle.py`, `.log` (diagnostic, an oracle term, not a hand-built weight): v18's clock and flip hold g (m1 − x) ± d cos(...), so their references m1 ± d / g partly lie above the largest, which is where its incomplete wipes come from. Subtracting each record's jump from all four from the step after the record (references then in [m1 − 2 d / g, m1]; the keep gate and position 9 corrected for the shift; exact at g = 10,000: 95.69% against 95.67%) removes every incomplete wipe but lowers accuracy at g = 10, 20, 50 from 92.1, 93.9, 95.1% to 82.9, 85.3, 87.7%: numbers just below the largest now partly switch the clock, and v18's readout is not built for that. So the trained network's references and its readout go together; moving v18's references alone trades one failure for another, as the wipe threshold did (`robust_twin/delta_probe.log`).
- Robustness check (`memory_as_slots_check.py`, `.log`): on other lists (seed 21), trained memory neurons matched by v18's slots and store: 0.97, 0.97, 0.86, 0.89, 0.87, 0.90 for 10, 11, 0, 12, 13, 14; 0.74 and 0.56 for 15 and 3; identical for v18 at gains 10 and 10,000.

## Corrections (2026-10-18; their checks are not included in this repository)

- The trained-scale gap is the structural tie, not partial switching. Records that leave the hiding group partly on are equally common in the trained network and in v18 at g = 10 (6.3% of records, about 8% of lists). Zeroing that leftover activity lifts v18 from 92.1% to 95.7% and the trained network from 95.3% to 95.7%. On those lists v18's median margin is 0.1, the trained network's 9.8; the leftover lifts a wrong position by about 1 and 5. So the trained network does not wipe better; it has about a hundred times more margin, because v18 hides only the record's jump (`../robust_twin/DESIGN.md`, the near-tie). The readings above that blame partial switching or incomplete wipes for v18's loss (the trade-off paragraph after `g50_v18.py`, and `g10_where.log`'s reading) describe where the loss shows, not why it is large.
- The overtaken record's tail in the trained network is small only in its sum over positions 0-8; single later positions reach +19 per unit against a revealed bump of 29-49, and position 9 takes −17 to −44.
- The trained network does not wipe "reliably": at records with jumps under 1% all four are off on only 4.5%, the summed leftover is 0.3 against 37; the last neuron switches off at a median 1.01-1.14 times the largest.

## Where the trained network's margin comes from at an overtaking (review direction 1)

- `margin_source.py`, `margin_fit.py`, `margin_split.py`, logs: lists where a record at r (the final second-largest) is overtaken at q by a number under 5% larger. The trained network is right on 89-98% of them, with a median margin of the right answer over the new largest's position of 5-8; v18 at gains 10,000 has margin exactly 0 (the new largest's position shows the previous largest's vote, equal to the revealed record's; the tie-breaker decides), and at gains 10 a negative median (−0.2 to −0.8). Fitted per placement, the trained margin is about 3 × x_r + 56-131 × (x_q − x_r), matching about half its variance. Per unit, when both numbers grow together (jump fixed) the revealed record's score rises 17-39 and the hidden largest's 12-33, so at a near-tie the trained network keeps a margin of about 5-7 per unit of value; when only the jump grows, early placements (records at 1-2) push the new largest's position down by 80-95 per unit and lift the revealed record by 39-47, later placements by only 6-9.
- Reading (interpretation): the trained network shows less of the current largest's value at its position than an overtaken record shows at its own, by about a fifth of a vote per unit of value, plus a strong jump-dependent push at early placements. v18 hides exactly the jump and nothing of the previous largest, so its overtakings are ties by construction.
- `margin_oracle.py`, `.log` (oracle, diagnostic): pushing the current largest's final score down by eta × vote × the largest lifts v18 at gains 10 from 92.1% to 92.9, 93.3, 93.7, 94.0% at eta 0.05, 0.1, 0.2, 0.3, and changes nothing at gains 10,000 (95.97-95.99%, where the tie-breaker already settles these ties). So a value-proportional margin recovers about half of v18's trained-scale loss; zeroing the incomplete wipes' leftover recovers all of it (review's check). A hand-built version would need the hidden largest to show less than the previous largest's full vote and the reveal to add it back, which in v18's layout means a wave height of the jump plus a fraction of the previous largest, between v18's rule and the 'height from the largest' misreading. Not built.

- `second_comparator_cutoffs.log` (review's cheap check): networks other than ARC with a hiding neuron whose weight on the new largest is below a cutoff times its weight on the previous largest, one step after a record: 4, 6, 7, 10 of 17 at cutoffs 0.1, 0.2, 0.3, 0.5. The post gives the range.

- `memory_control.py`, `.log` (review's cheap check): memories fed v18's newest-slot value each step (its gated votes plus the copied hiding wave), read together with v18's store. Variance of trained memory neurons 0, 3, 10-15 matched: v18's delay line 0.86, 0.56, 0.97, 0.97, 0.90, 0.87, 0.90, 0.75; random rotating memories (three seeds) 0.81, 0.54-0.56, 0.96, 0.96, 0.88, 0.87, 0.88, 0.65-0.73; a leaky-integrator bank 0.81, 0.56, 0.96, 0.96, 0.88, 0.87, 0.88, 0.73. So the earlier reading 'the trained memory is close to a linear re-coding of v18's delay line' should read: the trained memory holds about what v18 writes into memory (which numbers are kept, with what vote, plus the hiding wave); the delay-line structure itself adds 0-5 points over generic linear memories of the same writes.
- `hiding_corr_wave.py`, `.log` (review's cheap check): the hiding groups' shared level carries 91% of the trained group's variance, and the two groups' means correlate at 0.98. With each group's mean removed, v18's clock neurons match trained 7, 6, 8 at 0.73, 0.63, 0.74, and the flip matches trained 1 at only 0.18 (against 1.00, 0.96, 0.91, 0.93 with the level in). So the one-to-one hiding match is mostly the shared level; the turning patterns agree moderately for the three clock neurons and not for the flip. This also qualifies the per-neuron 0.82-0.99 for the hiding neurons in `faithful_plugin.log`.
