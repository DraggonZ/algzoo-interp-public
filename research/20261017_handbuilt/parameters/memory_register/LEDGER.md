## Branch r1a (round 1)

Plan (written before checking FINDINGS.md). The shift rule S-5 failed because it chains: each row is built from the previous *rule* row, so errors compound (0.40 relative). The mechanism does not need a chain. Position k+1's number is read one step after position k's, so at the end its trace is one step younger; for the readout to treat both alike, row k+1 must read a state the way row k reads that state one step later: W_oh[k+1, :] ≈ W_oh[k, :] D W_hh (D = which neurons are on at the end). If only the odd rows are covered, each is predicted from ARC's even row (uncovered, so stated anyway and free) and nothing compounds. A quick look (all neurons on, gain 1, memory columns only) gives row errors of 0.21-0.37 (rms) against the block's spread of 1.54 for rows 1, 3, 5, 7, and 0.48 for row 9. The other columns (hiding, store, gates) follow the shift badly (16-column relative error 0.2-0.98), so they are left uncovered at first. Then: (2) set D from the neurons' live on-rates at the end instead of "all on"; (3) see whether other groups' columns follow the shift with D.

It still nets only −8 to +2.5 bits, because each covered row pays 6 bits for its spread and the relation is only about 15-25% accurate per row. ## Branch r1b (round 1)

Plan (written before reading FINDINGS). The scorer charges 6 bits per covered row, so a rule pays only where it predicts weights far more precisely than the block's spread (0.53 for weights into the memory). Re-expressions (S-1) and loose relations (S-5) lose. The one relation known to be precise is blindness to the arriving number: a memory neuron's weights from the four hiding neurons (which carry about −11 × the arriving number) cancel that number. Solved for the weight from hiding neuron 7 (the largest input weight, −13.2), it predicts that weight from the row's other, uncovered weights to about 0.001-0.003, against a spread of 0.53: about 8 bits per row against the 6-bit row charge. Zero fitted constants except one shared gain (the scorer needs at least one constant). First try: the eight memory rows. Then: look for a second precise relation per row, so each row's 6-bit charge buys two weights. FINDINGS (sections 1-3) lists blindness as a known invariant (13 rows, KL 0.019) but nothing scored with this scorer, so nothing is rerun.

It explains nothing about how the network computes: zeroing those weights in ARC costs KL 7.7 and drops accuracy to 51%, so they are small but not idle. Under the handoff's rule that changes in how weights are priced are accounting conventions, it is not counted. Recommendation: if the lookup table is to be a fair baseline, input weights need their own reference spread. That would change every net figure in both loops, so it was not done here.
- r5b's other findings: the memory reads the hiding neurons only through ±1 sign patterns (pair differences such as h7 + h8 − h1 − h6, cosine 0.99-1.00); equal signs are blindness; the largest difference lies along the keep gate's column into the memory (cosine 0.96). As a rule with fitted constants it lost 41-105 bits. The memory supplies two-thirds of the keep gate's input.
- r5a's failure: giving some push equations to block rows instead of readout rows predicts block rows 14 and 15 within 9-15%, but it is a wash (−6 to −27): each push equation buys about the same bits wherever it is spent. The block needs a relation independent of the push. Each remaining block row would be worth +12 to +15 bits if predicted within 20%.
- Rounds 4 and 5 each gained only 5-6 bits on the block, just above the floor. Together with the hiding-rule leak (below, in progress), the target moves next round.

### Between rounds 5 and 6: hiding-rule leak and the v2 baseline (orchestrator)

Details: `hiding_leak/README.md`.

Same size in all six merged rules, so the method causes it, not one round. Restated leak-free (rows derived on the rule's own closed-loop states), `r5b_restore` scores **+99.8** (v1), against +96.8 as published, and passes the leak check.
